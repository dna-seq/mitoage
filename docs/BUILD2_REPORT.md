# MitoAge build 2: report

Build 2 of 2026-11-13, produced by `bun run data` on branch `build2-data`. The tables at the end are
generated by `bun run pipeline/report.ts <build 1 correlations.json>`; the comparison with the audit
tables is in `docs/BUILD2_CROSSCHECK.md` (`bun run pipeline/crosscheck.ts`). Open calls are in
`docs/BUILD2_OPEN_QUESTIONS.md`.

## Summary

- **2,335 species** = 922 from build 1 + 1,413 new. Build 1 species: 392 original, 465 updated, 46 renamed,
  19 retired (17 RefSeq records suppressed without a successor, *Carduelis pinus* whose only successor is
  another species' record, *Andrias davidianus* without a curated lifespan). 18 species switched to a live
  successor record and 2 to a new sequence version; 884 keep their accession.version.
- **New species** have a complete RefSeq mitogenome in release 237 and a curated lifespan: AnAge 838,
  FishBase 475, SeaLifeBase 74, USGS BBL 26 (provisional: EURING was not retrieved). Ids are
  10,000,000 + NCBI species taxid.
- **Changelog**: 14,392 rows (added 5,653, value_update 6,994, correction 1,639, renamed 87, retired 19),
  rule-scoped corrections for the complement-labelled base columns of build 1 and for the full-span
  counting of join() features. **Lifespan observations**: 7,197 rows from AnAge, FishBase, SeaLifeBase,
  USGS BBL and the build 1 value. **Review list**: 95 items. **Build 1** is frozen verbatim in
  `public/data/build1/` (34 parquet files and a README with the SHA-256 of every CSV).
- **Correlations** (computed at site build, decision D3): `default` 2,202 species (any curated source,
  no estimated, low- or questionable-quality lifespans), `anage_only` 1,710. Across all 1,257 features, r
  with log10 maximum lifespan in the two datasets correlates at 0.975 (scope all); 906 vs 1,037 features
  have q < 0.05. Example, whole-genome AT skew vs log10 lifespan (scope all): r = 0.336 in build 1 on 922
  species, 0.300 AnAge-only on 1,710, 0.311 extended on 2,202; the PIC r is about 0.1.

| lifespan observations (species, source, record id) | 7,197 = 7,197; values 7,197/7,197; `is_chosen` 6,888/7,197 (the 154 ties count twice, plus *Andrias davidianus*, whose build 1 value is marked chosen) |
| changes to build 1 species, same (table, row key, field) | 3,325 keys: values 99.0%, change_type 99.4%, diff_class 98.1% |
| RefSeq status vs NCBI esummary | 884 live = same version; 2 new versions; 17 suppressed without successor = retired; 18 successors, all among the audit's candidates; *Carduelis pinus* retired (the audit listed a successor that is another species' record) |
| renames | 47 of 48 renamed rows equal the audit's NCBI species name; *Carduelis pinus* takes the name of its AnAge species (*Spinus pinus*), not of its record's (*Spinus spinus*) |

Every disagreement has one of these explanations:

1. **Design choices** (defaults and open questions): class labels not taken from AnAge build 15 (212 audit
   rows `anage_taxonomy_revision`, of which 210 are `class`); renames only from NCBI, so AnAge-only renames
   (6), `duplicate_taxid` (2) and `organism_reassigned_in_ncbi` (2) are flags, not changelog rows;
   successors switched instead of retired (18 audit `retired` rows; the build 2 changelog has 5,394
   `refseq_successor` rows instead, with values compared against the new record); genus changes logged
   with a rename (39 `follows_scientific_name` rows).
2. **Retired species keep their build 1 rows**, so the audit's comparisons of 10 retired species against
   their suppressed records (about 70 region/codon rows and 4 `non_coding_bp` rows) have no counterpart.
3. **Successors and new versions** are compared against the new record (the audit compared against the
   cited one): all region/codon/feature keys of those 20 species differ in key set or value.
4. **Pinned release vs a later efetch**: *Pongo pygmaeus* NC_001646.1 was re-annotated on 2026-10-08,
   after the release 237 file; build 2 uses the release, which still matches build 1 (38 audit rows; 4
   feature rows in build 2).
5. **Aggregate naming**: 29 rows the audit classes `upstream_reannotation_same_version` on total_pc are
   `derived_from_upstream_reannotation_same_version` here (the aggregate inherits its genes' class).
